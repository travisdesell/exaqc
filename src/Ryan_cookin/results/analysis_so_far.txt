--------------------------------------------------------------------------------
0. What each stage actually does (in one line)
--------------------------------------------------------------------------------

  Stage A:  trained encoder + FIXED ansatz (RY-CNOT chain), N swept manually
  Stage B:  trained encoder + EVOLVED ansatz (CircuitGenome), N swept manually
  Stage C:  trained encoder + EVOLVED ansatz + EVOLVED N (grow/shrink_register)
  Stage D:  adds two new ENCODERS (linear_proj, reupload_euler) -- not a driver,
            consumed by Stage B and Stage C through --encoders flag
  Stage E:  EVOLVED encoder (feature-dep enc_ry/rx/rz, single-axis single-
            feature) + evolved ansatz + evolved N -- full co-evolution, weak
            encoder primitives
  Stage F:  Stage E redesigned with UNIVERSAL primitives. enc_rot is feature-
            dep universal-1-qubit (Rot(alpha,beta,gamma), 6 params). Two
            variants:
              v1 (hybrid)        : enc_rot + scalar rxx/ryy/rzz entanglers
              v2 (full feat-dep) : enc_rot + enc_xx/yy/zz feature-dep
                                   entanglers (3 params each)
            Tests "does packaging universal primitives into single gates
            beat composing them from simpler ones?"

--------------------------------------------------------------------------------
2. Per-stage pros and cons
--------------------------------------------------------------------------------

STAGE A (fixed ansatz baseline)
  Pros:
    - Cheapest to run (~30-60s per cell on Win machine). 64-cell sweep
      fits in ~30 min.
    - Deterministic, reproducible -- no evolution randomness. Bit-exact
      reruns with same seed match to 1e-9.
    - Easy to interpret: the ansatz is hand-built (RY + linear CNOT chain
      at depth=2), so a result tells you which (encoder, N) combo is best.
    - Useful as the "encoder choice only" comparison axis.
  Cons:
    - Hand-built ansatz is a confound: when a cell does badly you can't
      tell whether the encoder is bad or the ansatz can't use it.
    - Wide N sweep is mandatory because the structure is frozen --
      can't trade qubits for gates.
    - `fixed_amplitude` does very poorly here because N is fixed and
      doesn't match log2(D); evolved-N rescues this in C.

STAGE B (evolved ansatz, N swept)
  Pros:
    - All four champions live here. Hit ceiling on 3/4 datasets.
    - Best wall-time-per-cell vs Stage C (small fanout from evolution
      since N is still swept manually).
    - Cleanly isolates "does evolving the ansatz help?" relative to A.
      Answer: yes for `learned`/`linear_proj`/`reupload_euler`,
      negligible for `fixed_basis`/`fixed_angle`.
    - The "structure search" axis works for the universal encoders --
      Stage B + reupload_euler is the best practical workflow we found.
  Cons:
    - Manual N sweep means we pay 4x for each encoder/dataset combo.
    - Some cells with `gates=0` (~8% of B's 96 cells) -- evolution
      occasionally fails to add a gate due to a known add_gate
      limitation on small output-qubit sets. EXAQC retries but can
      stall in unlucky chains. Not a crash, just a wasted cell.
    - Single-seed; no error bars yet (multi-seed rerun in flight).

STAGE C (evolved ansatz + evolved N)
  Pros:
    - Best mean test_acc (0.862) of any stage. Strong sweep-level
      result.
    - Drops the N dimension from the sweep, so 4 cells per (dataset,
      encoder) become 1 cell -- way cheaper per encoder/dataset combo
      than B once you account for the N-axis.
    - Rescued `fixed_amplitude` by finding N = log2(D) automatically
      (iris went 4->2, test_acc 0.733 -> 0.900).
    - Genuinely "set and forget" for production: pick an encoder, run
      Stage C, done.
  Cons:
    - On the `learned` encoder, B->C delta is NEGATIVE on every
      dataset: manual N sweep beat evolved N at 80-genome budget.
      Suggests Stage C is budget-limited for that encoder.
    - Per-cell wall time is much longer than Stage B (especially
      breast_cancer: up to ~1100s for `learned`, ~660s for
      `linear_proj`, ~1145s for `reupload_euler`).
    - Pre-fix had two crashing bugs (register evolution + qubit_swap);
      both fixed 2026-05-21 but the search behavior is sensitive to
      those edge cases. Watch for regressions.
    - Same gates=0 noise as Stage B.

STAGE D (universal encoders)
  Pros:
    - HIGHEST-LEVERAGE CHANGE WE SHIPPED. `reupload_euler` mean acc
      0.983 (B) / 0.993 (C); `linear_proj` 0.972 (B) / 0.968 (C).
      That's a bigger gain than every level of evolution combined.
    - Encoder is universal: 3 Euler angles per qubit covers all of
      SU(2). Combined with reuploading depth=2, it can represent
      arbitrary feature-to-state maps that fit on N qubits.
    - Both encoders are smooth drop-in replacements for `learned` --
      same training loop, no special harness.
    - Initialization biases the first forward to match `fixed_angle`,
      so they don't start from a random unitary -- training is stable.
  Cons:
    - Largest parameter count of any encoder we tried (reupload_euler
      breast_cancer/N=10/depth=2 is 1860 params, vs 40 for `learned`
      at the same shape). This raises the "is it expressivity or just
      more params?" confound flagged in Stage A's original report.
    - No fairness control yet against `learned` + more ansatz layers.
    - Specifically vulnerable to overfitting on small datasets
      because of the high param count -- not visible at the current
      train/test split scale but worth checking with k-fold.

STAGE F (universal-gate-set co-evolution: v1 hybrid, v2 full feat-dep)
  Pros:
    - **HUGE improvement over Stage E.** v2 mean test_acc 0.904 vs
      Stage E's 0.790 -- the biggest stage-to-stage delta we've ever
      shipped, and decisive evidence that wrapping universal
      primitives into single gates helps evolution find them.
    - Encoder ceiling raised: v2 iris 0.967, wine 0.917 -- approaching
      the staged ceiling.
    - Same EXAQC machinery as Stage E; only the gate vocabulary
      changed. Cheap to extend.
    - Architecturally clean: enc_rot is universal 1-qubit (covers all
      of SU(2)); enc_xx/yy/zz are feature-dep entanglers that combined
      with enc_rot span universal 2-qubit operations via KAK
      decomposition. The gate pool *is* a universal basis.
  Cons:
    - Still loses to Stage B + reupload_euler by ~0.08 mean.
      Co-evolution remains harder than staging for these benchmarks.
    - v1 (hybrid: universal-1-qubit-feature-dep encoder + scalar
      2-qubit entanglers) is barely better than Stage E (0.804 vs
      0.790). **The feature-dependence of the 2-qubit gates is the
      key**, not the universality of the 1-qubit ones. This was not
      obvious before running both variants.
    - Single-seed only -- variance unknown. Strong recommend to
      multi-seed before drawing tight conclusions on the iris jump.
    - Param cost per cell is moderate but real. v2 cells used 5-14
      enabled gates total (more than Stage E's 4-9), reflecting the
      richer pool.
    - Longest cell so far: breast_cancer v1 at ~777s, v2 at ~709s.

STAGE E (fully evolved encoder + ansatz + N)
  Pros:
    - The "most automated" formulation -- you pick a dataset and
      EXAQC decides everything else.
    - Encoder gates use feature-dependent rotations (R<axis>(a*x[q%D]
      + b)) directly, so the encoder structure is genuinely part of
      the genome (not a separate module).
    - Successfully exercised the full evolution machinery: 120+
      genomes, register growth on every dataset (all 4 grew to N=5
      or N=6 from initial N=4), nontrivial encoder gate counts (4-5).
  Cons:
    - LOSES on every dataset relative to the best of A/B/C, by
      0.123 (breast_cancer) to 0.300 (iris). Worst per-cell delta of
      any stage.
    - **Stage E v2 (300 genomes) CONFIRMS it is not budget-limited.**
      2.5x compute changed mean test_acc by -0.003 (0.790 -> 0.787).
      Iris actually got worse (0.700 -> 0.633). Gate counts grew
      (iris evolved enc=10, ans=11) but accuracy did not.
    - The enc_ry/rx/rz feature-dependent gates are each a single
      feature reference (a*x[q%D] + b), not a full feature mixing
      linear projection. This is fundamentally weaker than the
      universal Stage-D encoders that mix all D features per axis.
      No amount of evolution recovers expressivity that's missing
      at the per-gate level.
    - In practice, Stage E is a strictly worse choice than Stage B
      + reupload_euler on every dataset tested.

3. Per-encoder pros and cons (across Stages A, B, C)
--------------------------------------------------------------------------------

fixed_basis (computational-basis encoding via thresholding)
  - Mean acc: A 0.678, B 0.618, C 0.654
  - Pros: zero trainable params, interpretable (each qubit = "feature i
    above median"), reproducible.
  - Cons: discretizes the input (throws away continuous info), and the
    A->B delta is negative on most cells -- ansatz evolution can't
    recover info the encoder destroyed. Consistently the worst encoder.

fixed_angle (RY(pi*x_q) per qubit, no train)
  - Mean acc: A 0.785, B 0.753, C 0.844
  - Pros: zero trainable params, simple. Reasonable baseline; preserves
    continuous structure.
  - Cons: feature-to-qubit assignment is trivial (q -> x[q%D]); no
    feature mixing. C does much better because evolved N adapts the
    register to the encoder's natural scaling.

fixed_amplitude (AmplitudeEmbedding, zero-padded, no train)
  - Mean acc: A 0.493, B 0.534, C 0.832
  - Pros: information-theoretic ideal -- packs D features into log2(D)
    qubits. Explodes under Stage C because evolved N finds the right
    width.
  - Cons: catastrophic outside its natural N (the A and B sweeps had to
    use N >= 4 which is too big for iris/D=4 -> 2-qubit ideal). When
    N > log2(D), zero-padding pushes the state into a tiny subspace.

learned (RY(a*x[q%D] + b) with 4N trainable params)
  - Mean acc: A 0.871, B 0.903, C 0.882
  - Pros: cheap trainable encoder (4N params), each qubit gets a
    learnable affine on its natural feature. Iris/learned/N=4 was the
    Stage B champion at test_acc=1.000.
  - Cons: only sees ONE feature per qubit (no cross-feature mixing).
    Saturated by Stage B -- adding evolved N (Stage C) doesn't help and
    sometimes hurts. Outperformed by the universal encoders almost
    everywhere.

linear_proj (RY(W*x + b), full N*D matrix)
  - Mean acc: A n/a, B 0.972, C 0.968
  - Pros: full feature mixing per qubit. Wine champion (1.000, B/N=4).
    Strictly more expressive than `learned` (which is the diagonal
    special case).
  - Cons: ~depth*(D+1)x more params than `learned`. No A baseline
    (was added in Stage D). Stage B already saturates so Stage C
    doesn't add much.

reupload_euler (Rot(a, b, g) per qubit, each Euler angle a learned
linear function of features, depth=2)
  - Mean acc: A n/a, B 0.983, C 0.993
  - Pros: BEST OVERALL. Universal single-qubit unitary capacity per
    qubit, every Euler angle is a feature-mixed linear map. Three
    champions (seeds, breast_cancer, also ties on wine).
  - Cons: largest param count of any encoder. With depth=2 it's
    3*2*N*(D+1) params, e.g. 1860 for breast_cancer/N=10. The "is it
    more expressive, or just more params?" question remains open
    until a fairness experiment runs.

4. Per-dataset winner analysis
--------------------------------------------------------------------------------

IRIS (D=4 features, K=3 classes, 150 samples)
  - Champion: Stage B, learned, N=4 -> 1.000 (3 gates)
  - Close seconds: Stage B/C reupload_euler at N=4 (both ~1.000)
  - Notable: iris is small enough that almost any reasonable
    (encoder, ansatz) hits 0.97+. Stage C shrinks `fixed_amplitude`
    from N=4 to N=2 and rescues it from 0.733 -> 0.900.
  - Best ansatz size: 3-6 gates. Tiny circuits, no need for depth.

WINE (D=13, K=3, 178 samples)
  - Champion: Stage B, linear_proj, N=4 -> 1.000 (5 gates)
  - Close seconds: Stage B reupload_euler ~1.000; Stage C
    reupload_euler ~1.000 at N=4.
  - Notable: hardest dataset for `fixed_basis` and `fixed_amplitude`
    (thresholding loses too much; D=13 doesn't fit cleanly into
    log2 spread).
  - Best ansatz size: 2-5 gates.

SEEDS (D=7, K=3, 210 samples)
  - Champion: Stage B, reupload_euler, N=6 -> 1.000 (2 gates)
    Co-champion: Stage C, linear_proj, N=4 -> 1.000 (1 gate)
  - Notable: Stage A's best was 0.881 (learned/N=8); Stage B
    pushed it to 1.000. Biggest single-stage improvement over A.
  - Best ansatz size: 1-3 gates. Stage C found a 1-gate solution
    for linear_proj.

BREAST_CANCER (D=30, K=2, 569 samples)
  - Champion: Stage B, reupload_euler, N=4 -> 0.974 (2 gates)
    Co-champion: Stage C, reupload_euler, N=6 -> 0.974 (1 gate)
  - Notable: only dataset that doesn't hit 1.000 (ceiling at
    ~0.974). Stage A's best (learned/N=6) was 0.895, so universal
    encoders + evolution pushed it +0.079.
  - Best ansatz size: 1-7 gates. Stage C breast_cancer cells
    were the slowest cells in the entire sweep (~1100s for
    `learned`, ~1145s for `reupload_euler`).

5. Cross-cutting trends
--------------------------------------------------------------------------------

TREND 1 -- Encoder choice >> evolution
  The single biggest accuracy lever is the encoder family. Going from
  `learned` to `reupload_euler` (Stage D's contribution) gives
  ~0.08-0.10 accuracy on average, which is more than the A->B->C
  evolution stack contributes combined.

TREND 2 -- Evolution helps but with diminishing returns
  Per-stage mean acc deltas: A->B +0.087, B->C +0.068. Both positive
  but shrinking. Stage E (full co-evolution) is a regression at
  current budget -- not strictly monotone.

TREND 3 -- Small N wins
  Mode of evolved N in Stage C is N=4 (14/24 cells). Champions all
  use N <= 8. The "throw more qubits at it" narrative is wrong for
  these classification problems at this scale.

TREND 4 -- Champion circuits are TINY
  Champion gate counts: iris 3, wine 5, seeds 2, breast_cancer 2.
  None of the best circuits have more than 5 enabled gates. The
  ansatz is doing very little work once the encoder is strong.

TREND 5 -- Evolved N has narrow but real value
  Only valuable when the encoder has a "natural" N (amplitude
  embedding -> log2(D)). Otherwise the manual N sweep is
  competitive. For `learned`, evolved N actually hurts -- the
  manual sweep gets to try 4 widths in parallel.

TREND 6 -- Stage E ceiling is architectural, but Stage F lifts it
  Stage E v2 (2.5x budget) confirmed the Stage-E ceiling isn't budget-
  limited (mean -0.003 vs v1). Stage F v2 (same budget as Stage E v1)
  jumps the ceiling to mean 0.904 by changing the gate vocabulary to
  universal primitives -- enc_rot (universal 1-qubit feature-dep) and
  enc_xx/yy/zz (feature-dep entanglers). **Confirms it was the gate
  set that was limiting Stage E, not the search.** With universal
  primitives, co-evolution closes most of the gap to staged designs
  (Stage B + reupload_euler is ~0.987, F v2 is 0.904 -- about 0.08
  apart, vs 0.20+ for Stage E).

TREND 6b -- Universal 1-qubit isn't enough; entanglers need data too
  Stage F v1 (universal-1-qubit feature-dep + SCALAR 2-qubit
  entanglers) is only +0.014 over Stage E. Stage F v2 (same encoder +
  FEATURE-DEP 2-qubit entanglers) is +0.114. **The +0.100 difference
  is the data-dependence of the entanglers**, not the universality of
  the 1-qubit gates. Surprising in retrospect -- we expected universal
  1-qubit to be the main lever, but it's the joint feature mixing
  through entangling gates that does most of the work.

TREND 7' -- Multi-seed stability separates the encoders sharply
  With 3 seeds on Stage C, reupload_euler has zero std on 2/4
  datasets (wine, breast_cancer) and tight std on the rest (max
  0.019). linear_proj has tight std too (max 0.039). `learned`
  has the widest spread (std up to 0.080 on wine). Seed=0 results
  for `learned` are noisy and can be misleadingly good or bad;
  reupload_euler results are robust.

TREND 8 -- `fixed_basis` is the only encoder ansatz evolution hurts
  A->B delta is negative on most fixed_basis cells. The encoder
  produces one of a small set of computational basis states; the
  ansatz mostly destroys that structure rather than exploiting it.
  Hard to imagine a useful production setting for `fixed_basis`
  given current results.

6. Recommendations / what to do next
--------------------------------------------------------------------------------

WHAT TO USE IN PRACTICE (single best recipe, multi-seed-validated)
  Stage B + reupload_euler + N=4 (start there, optionally try N=6
  on small-feature datasets) + CircuitGenome evolution with
  n_genomes=50, pop_size=20. Empirically wins or ties on every
  dataset across 3 seeds, with std typically 0.000-0.024 at the
  champion cell. Fallback if reupload_euler param count is too
  high: linear_proj with the same recipe (within 0.004 mean acc,
  1/3 the encoder params).

WHAT TO NOT BOTHER WITH
  - `fixed_basis` -- unrecoverably weak across all stages.
  - Pushing Stage A further -- it's a baseline, not a contender.
  - Wider N sweeps in Stage B -- N=4 wins for nearly every
    champion; the extra cells don't add information.
  - Higher reupload depth in reupload_euler -- already at depth=2
    and saturating accuracy; more depth costs params for no gain.

OPEN QUESTIONS THAT DATA HASN'T SETTLED
  - Does the universal-encoder dominance hold under noise? All

    enabled noise; should re-run the 3 winners with IBM noise model

    would be 4x50 = 200 genomes per cell.
  - Are these results reproducible on a different machine? Stage A

    randomness; multi-seed reruns will quantify.
